# Coding Agent 交接提示词

请基于我现有的 `yangshengguo46-stack/marketing-system-v7` 仓库实施。

首先读取 `docs/superpowers/marketing-agent-v7/README.md`，按入口规定的顺序读取 `v1.2/BUSINESS_ARCHITECTURE.md`、`v1.2/FINAL_SPEC.md`、`v1.2/IMPLEMENTATION_TASKS.md`、`v1.2/SOURCE_MAP.md` 及当前工作包所需合同。

这是实施任务，不是再设计一套替代架构。先核对当前分支、HEAD、未提交改动及真实代码符号，在独立开发分支推进；不回退或覆盖用户工作。文档中 NEW 接口是目标合同，必须按真实源码适配，不能当成已有 API。

继续 v7、原生 Codex 循环和同一个 Lead；Core 可以修改，不再把持续同步上游作为硬约束。不创建 v8、第二个营销总调度器、核心营销 MCP 或固定业务工作流。不要让内部每一种思考都变成一次额外模型调用。

先核对仓库已有的产品交付约定、六版失败记录、编剧课导读、与当前任务相关的完整课节、`story-work-v1` 方法和试用边界。课程整理完整不等于已经证明方法有效，保留候选状态和阴性结果。

按规格真正写好并接入专业身份、`lead-context.md`、`marketing-judgment.md` 和 `manifest.json`，不留方法名称或空文件作占位。场景、Actor、Transformation、Primitive/Operator、事件与视角、Candidate 和 Intervention 是同一个 Lead 可使用的专业判断，不是必填表或强制步骤。局部改稿、演示、证明和数据诊断不被强迫故事化。

从 WP00+B00 开始；B01/B02 与 WP01–03 同步；尽早完成 WP04+B03 的一个真实任务完整交付。首次使用、空客户历史记忆下就应能提供业务价值。不能只返回画像、选题目录、分析字段或方法说明，也不能让客户承担专业创作指导。

作品不可采用时，先定位业务理解、资料、方法或模型的问题，不通过扩大数据库、平台和 UI 掩盖失败。

每包按实际仓库规则写针对性测试、实施、验证并报告：改了什么、跑了什么、哪些通过、完整作品是什么、客户/外部模型帮助有多少、未验证项与回滚方法。编译通过、文件保存、模型自评与真实业务增益分开报告。

生产验证使用我已配置并明确获授权的模型；不得默认依赖 GPT-6 替生产模型修稿。付费调用、公开发布、破坏性迁移和推送/合并远端默认分支需对应授权。没有授权先完成不依赖它们的工作。

不要只交新的规划文档。已明确范围内的实现细节自行解决；影响产品方向、数据安全、费用或外部行为的重大变化再提出确认。
