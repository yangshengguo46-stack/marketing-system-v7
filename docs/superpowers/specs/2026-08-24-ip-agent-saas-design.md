# AI IP 内容与生成式制作 SaaS 设计规格

- **日期：** 2026-08-24
- **状态：** 规格 v1.2 当前基线；v1.1 为用户确认业务规格，v1.2 于 2026-08-25 加入前六轮系统审计护栏，业务范围不变；后续变更须记录影响范围与新版本
- **目标市场：** 中国大陆用户为主；首版重点服务抖音、小红书内容，保留服务海外 TikTok 业务题材的能力，但不直接接入 TikTok 发布接口
- **模型与媒体供应商：** 火山引擎 / 火山方舟 / 豆包体系

## 1. 产品定义

本产品是一套面向商家的 AI IP 内容与生成式制作 SaaS。它不是单一聊天机器人，也不是只会根据商品关键词生成文案的工具。系统需要完成从商家访谈、IP 策略、研究、选题、营销叙事、编导制作、AI 成片、人工发布、数据回收，到策略学习的完整闭环。

系统的核心价值是：

1. 从“我是谁、卖什么、卖给谁”出发，判断商家提供的是商品、服务、机构、经营方式还是人物身份，并形成可验证的用户画像，避免直接套用相邻行业模板。
2. 像有经验的新媒体运营和编导一样，找到可持续的人物、事件、关系、欲望与冲突。
3. 把内容策划转化为可以真人拍摄、数字人呈现或 AI 情景剧生成的成品。
4. 发布前记录预测，发布后用真实数据和评论修正当前 IP 的经验。
5. 通过一级代理、二级代理和 C 端用户的预充值额度体系完成商业化。

产品采用“阶段化工作流＋按需专家 Agent”，不采用一个大提示词，也不采用无边界自由讨论的多 Agent 群聊。

## 2. 首版目标与非目标

### 2.1 首版目标

- 中国大陆 C 端用户可创建多个相互隔离的 IP 项目。
- 完成约 20 分钟的引导访谈，并上传人物、业务、产品、案例和历史内容资料；系统据此区分购买者、使用者、受益者、影响者和渠道，并生成待用户确认的核心用户画像。
- 输出三个具有实质差异的 IP 策略方向，由用户选择并冻结为版本。
- 主动检索公开网络信息，并分析用户提交的对标链接或材料。
- 生成选题池、周计划、营销构型、口播/纪实/剧情/产品展示方案。
- 生成抖音与小红书差异化内容版本。
- 正式支持 Seedream 图片、Seedance AI 情景镜头、豆包标准 TTS 和自动后期。
- 支持真人拍摄生产包、AI 情景剧及混合制作。
- 克隆数字人口播以 Beta 形式存在，受账号权限、授权和稳定性闸门控制。
- 用户手动发布，提交链接、表单或截图回收 T+1、T+3、T+7 数据。
- 使用发布前预测、数据对照、评论洞察和项目记忆形成学习闭环。
- 支持平台、一级代理、二级代理、C 端用户和创作点账本。

### 2.2 首版明确不做

- 不直接登录或自动发布到抖音、小红书或 TikTok。
- 不建设大规模平台爬虫。
- 不接 C 端微信、支付宝在线支付和自动分账。
- 不支持三级及更深代理层级。
- 不支持团队协作、项目负责人、编辑和只读成员等团队版角色。
- 不根据少量数据自动微调基础模型。
- 不自动把一个 IP 的私有经验用于另一个 IP。
- 不把传统克隆数字人口播承诺为正式 SLA 能力。
- 不在首版提供全平台内容适配；抖音和小红书为正式适配平台。

## 3. 首批验证项目

固定使用以下五类项目压测系统：

1. **水果**：商品大类、产地、产业链、季节和现实事件。
2. **黄金礼品**：商品材质与送礼行为、人情关系、礼俗和商业承接。
3. **TikTok 直播公会**：机构、主播、平台和商业利益网络。
4. **本系统自己营销自己**：平台作为一个真实 IP 项目，分别面向一级代理、二级代理和 C 端用户识别购买关系、建立画像并生产内容；必须使用与客户项目相同的完整工作流，不能调用特制宣传模板。
5. **宝妈素人**：人物身份信息不足，系统必须给暂定探索方向并继续访谈，不能自动生成育儿账号方案。

五类项目共同验证：系统能否先识别“我是谁、卖给谁以及为什么会成交”，再决定研究、故事和内容路径，而不是套固定行业公式。第四类同时执行内部实战检验：系统必须能够用自己的能力获得关注、信任和业务行动，并用真实发布数据暴露自身工作流的问题。固定情景测试另设“只给出身份标签或销售方式”的反例输入，确保系统会继续澄清而不会把经营方式直接当成内容主题；该反例不作为第六个真实项目。

## 4. 用户与商业关系

### 4.1 固定账户层级

```text
平台
└── 一级代理
    ├── 二级代理
    │   └── C 端用户
    └── C 端用户
```

- 一级代理可以创建二级代理和直属 C 端用户。
- 二级代理只能创建直属 C 端用户。
- 首版平台只向一级代理线下收款并充值创作点。
- 一级、二级代理分别向自己的下级线下收款，并在平台内划拨创作点。
- 代理属于商业渠道角色，不属于内容协作角色。
- 每个 C 端用户可创建多个 IP 项目，但不能邀请其他成员共同编辑。

### 4.2 内容隐私

代理默认只能看到下级账户、余额、额度流转、消费汇总和售后状态，不能读取 C 端用户的访谈、脚本、人物素材、声音或视频。

C 端用户需要代理协助时，可发起有期限、有范围的支持授权。所有代理访问均进入审计日志。

### 4.3 平台自营销项目的责任主体

- 平台管理员创建平台内部运营账号、指定自营销项目负责人并设置内部预算，但不代替负责人作内容决策。
- 平台内容运营负责人回答访谈、确认画像、选择策略、发起制作、完成普通内容审核、人工发布并回收数据。
- 触及高风险营销主张、授权真人、客户案例或重大争议议题时，由独立的平台审核人批准后才能进入待发布状态。
- 这些是平台内部权限，不属于面向 C 端销售的团队版，也不进入一级、二级代理关系树。
- 项目负责人、审核人、预算批准人及其每次操作都写入审计日志；任何人不能通过内部身份绕过事实、授权、质检或预算闸门。

## 5. 产品操作流程

```text
创建 IP 项目
→ 引导访谈与资料上传
→ 回答五个商业根问题
→ 信息充分性诊断及必要基础核验
→ 生成并确认核心用户画像
→ 三个策略方向
→ 用户选择并冻结策略版本
→ 联网研究与对标分析
→ 选题池 / 周计划
→ 营销叙事构型
→ 编导与平台适配
→ 制作方式路由
→ 真人生产包或 AI 成片
→ 事实、权利、媒体质量审核
→ 发布前预测
→ 用户手动发布
→ T+1 / T+3 / T+7 数据回收
→ 评论洞察与复盘
→ 更新当前 IP 的候选经验
```

用户界面以项目状态和下一步行动为中心，不以无限聊天为中心。聊天用于访谈、纠错和局部重写；策略、选题、脚本、媒体、发布与复盘使用结构化页面。

每个 IP 项目在入驻时设置一次营销风险偏好：克制、平衡或激进；默认使用“平衡”。该偏好只影响开头强度、悬念和修辞，不允许降低事实、授权和商品真实性标准。

## 6. 系统总体架构

### 6.1 设计原则

- 首版采用模块化单体与独立任务 Worker，不拆成大量微服务。
- PostgreSQL 是用户、账本、任务、版本和审计的唯一事实来源。
- Redis 只用于缓存、限流和短期协调，不保存最终余额或任务真相。
- RocketMQ 只负责通知 Worker 处理任务，所有消息按可能重复、延迟和乱序设计。
- 媒体文件保存于私有 TOS；模型返回的临时链接不是永久交付地址。
- 所有模型通过能力网关调用，业务代码不写死具体模型版本。
- 每个高成本步骤先估算并冻结创作点，再调用供应商。

### 6.2 逻辑结构

```text
平台后台 / 一级代理 / 二级代理 / C 端网站
                    ↓
              普通 API 网关
                    ↓
             核心业务服务
        ┌───────────┼───────────┐
        ↓           ↓           ↓
   PostgreSQL     Redis        TOS
        ↓
   Outbox / 持久化任务状态
        ↓
     RocketMQ
        ├── Agent Worker
        ├── 研究 Worker
        ├── 图片/视频 Worker
        ├── TTS/数字人 Worker
        ├── FFmpeg 后期 Worker
        ├── 媒体质检 Worker
        └── 结算/复盘 Worker
                    ↓
              火山能力网关
        ├── Responses API
        ├── Seedream
        ├── Seedance
        ├── 豆包语音
        └── 数字人 Beta 接口
```

## 7. Agent 角色与制约

以下是逻辑职责，不等于每个 Agent 都部署成独立服务，也不表示每轮必须依次调用全部角色。一个总运营编导（Lead）拥有最终业务判断和正式提案权；其余角色只在任务需要时提供有边界的证据、诊断、创作或审核结果，不通过固定投票决定定位，也不拥有第二套业务状态。多个低频角色可以共享 Worker，但必须保留独立输入输出协议。

### 7.1 流程编排器

- 根据项目和内容状态决定下一步骤。
- 强制执行用户确认、事实审核、授权、扣费和媒体质检闸门。
- 不自行决定 IP 定位，不直接创作文案。

### 7.2 访谈诊断 Agent

- 输入：用户回答、上传资料、历史内容。
- 输出：结构化项目档案、五个商业根问题的当前答案、购买关系、用户画像、信息缺口和暂定探索方向。
- 必须区分购买者、使用者、受益者、影响者、推荐者和渠道；这些角色重合时可以合并，不重合时不能强行写成同一个“目标用户”。
- 信息不足时先指出缺口，并提供若干暂定方向，再逐项访谈。
- 画像确认前可以执行范围受限的基础核验；策略选定后的研究 Agent 再完成选题所需的深度研究，二者不能互相替代。
- 不根据“宝妈”等身份标签或某种经营方式自动套相邻内容赛道。

### 7.3 IP 策略 Agent

- 在用户确认核心画像后，输出三个具有不同故事来源、人物结构和商业连接的候选方向。
- 项目存在多个画像或受众轨道时，三个候选仍是项目级总 IP 方向；每个候选必须分别说明怎样服务各轨道，不能只适配其中一个主要画像。
- 用户只选择一个项目级总方向。选定后，每个轨道生成自己的内容承诺、信任证据、栏目和行动路径，但不能改变总 IP 的人物身份、核心立场和长期叙事。
- 每个方向包含长期追问、核心人物、反复事件、主要矛盾、独家素材、内容栏目、商业连接和失效条件。
- 三个方向不能只是语气和包装变化。
- 最终选择权属于用户。

### 7.4 研究与对标 Agent

- 研究公开网络、用户上传资料和用户提交的对标链接。
- 区分事实、当事人陈述、推断和观点。
- 对标分析学习内容结构，不复制具体文案或模仿特定创作者个人语言。
- 外部网页一律视为不可信数据，不执行网页中的提示词或操作指令。

### 7.5 选题 Agent

- 把策略和研究转化为包含人物、变化、选择、代价和观看问题的选题。
- 输出选题卡，不只输出标题。
- 说明选题与策略、平台、业务、素材和风险的关系。

### 7.6 营销叙事 Agent

负责判断怎样让观众停下、误判、好奇、相信和传播，输出：

- 观众当前相信什么。
- 第一秒看到什么。
- 希望观众暂时形成什么判断。
- 暂时隐藏哪部分真实信息。
- 在哪里揭示。
- 揭示后产生什么情绪和观点变化。
- 如何连接业务。
- 负面理解和品牌风险。

它可以选择结果先行、反常识、利益对立、身份冲突、真相延迟、实验对比、故事代入等结构，但不能制造不存在的事实。

系统采用“完整叙事审核”而非“每句必须立刻完整”的方式：允许观众暂时误解，不允许内容最终欺骗；允许延迟真相，不允许篡改真相。

### 7.7 编导 Agent

- 将营销构型转化为可拍或可生成的内容。
- 支持真人口播、纪实记录、剧情演绎和产品展示。
- 输出创作母版、逐字稿/场景剧本、分镜、场地道具、声音、字幕、素材和低成本替代方案。
- 不能把虚构客户故事包装成真实经历。

### 7.8 平台适配 Agent

- 保留同一核心故事，分别重组抖音和小红书版本。
- 抖音重点处理第一视觉/第一句话、口语节奏、连续悬念和评论入口。
- 小红书重点处理标题封面、经历情境、收藏搜索价值、字幕和正文补充。
- 平台规则带版本，不把某次有效公式永久化。

### 7.9 IP 人格校准 Agent

- 判断内容是否像这个具体的人会说、能说、愿意说。
- 维护语言习惯、价值边界、能力、经历和镜头表现方式。
- 防止所有项目被写成同一种“爆款腔”。

### 7.10 事实与风险审核 Agent

- 后台维护事实底座，不把成片改成论文。
- 重点审核会影响购买或公众判断的可验证主张：功能、功效、产地、价格、收益、政策、统计、证言和前后对比。
- 观点可以鲜明，修辞可以大胆，但不能虚构或隐去足以推翻商业结论的关键条件。
- 可将内容退回修改或阻止进入待发布状态。

### 7.11 制作方式路由 Agent

根据题材、真实素材、预算、授权、镜头复杂度和历史表现推荐：

- 真人拍摄。
- AI 情景剧。
- 固定虚拟角色。
- 真人素材与 AI 画面混合。
- 客户本人克隆数字人 Beta。

### 7.12 多模态导演与媒体 Agent

- 角色与数字身份管理 Agent：管理角色设定、形象、声音、授权和连续性。
- 分镜与生成任务 Agent：把场景拆成可独立重做的镜头任务。
- 后期制作 Agent：完成剪辑、配音、声音、字幕、包装和平台导出。
- 媒体质检 Agent：检查人脸、手部、口型、声音、连续性、商品真实性、字幕、音量、授权和 AI 标识。

### 7.13 预测复盘、评论洞察与记忆 Agent

- 发布前冻结预测和主要实验变量。
- 发布后比较账号自身历史基线，而非跨账号绝对值。
- 评论洞察提取观众的复述、误解、欲望、反对和追问。
- 单条内容只生成观察或候选假设，不能自动改写策略。
- 记忆规则保存适用范围、支持案例、反例、信心和最近验证时间。

## 8. 核心策划推理

### 8.1 五个商业根问题

系统不从“这个行业能讲什么”开始，而是先连续回答以下五个问题：

1. **我是谁？** 明确真实身份、业务阶段、经历、立场、可调用资源、独家素材和现实限制，判断什么话能由“我”可信地说、长期地说。
2. **我的产品或服务要卖给谁？** 明确谁付钱、谁购买、谁使用、谁受益、谁影响决策、谁负责推荐或分销，不能用宽泛人群标签代替真实交易关系。
3. **对方为什么会买，又为什么可能不买？** 找到具体购买场景、触发事件、想获得的改变、隐性动机、机会成本、风险和反对理由。
4. **对方为什么相信我、选择我，而不是别人？** 找到可展示的证据、差异、关系基础、过程透明度、案例、权威来源和长期一致性，不能用自我评价代替信任依据。
5. **什么内容能让对方从陌生走到行动？** 分别设计停留、理解、关注、信任、咨询或购买等阶段目标，并明确每条内容只推动一个可观察的下一步行动。

前两问确定“谁在卖、卖给谁”，后三问把宽泛受众收敛为可创作、可验证、可转化的用户画像。五个答案都要版本化，并关联用户材料、必要的基础核验或明确标记的假设及信心等级；资料不足时继续提问，不能把推断写成事实。

### 8.2 用户画像不是人口标签

每个项目至少确认一个核心画像；存在明显不同的购买角色时，可建立多个次级画像，但不同画像的内容假设和数据必须分别记录。每张画像卡至少包含：

- 画像名称及其在交易中的角色。
- 与创作者、产品、付款者、使用者和受益者的关系。
- 进入购买状态的具体情境与触发事件。
- 功能、情绪、身份和关系层面的期望结果。
- 担忧、反对、替代方案、决策成本和不购买原因。
- 决策权、预算来源、决策链和可能的阻碍者。
- 能建立信任的证据以及会破坏信任的信号。
- 对方自己的表达方式、信息来源和常用平台。
- 从看见内容到咨询、试用、购买或转介绍的最短合理路径。
- 每项判断的来源、信心等级和推翻该判断的条件。

“25—40 岁女性”“宝妈”“老板”只能作为线索，不能单独构成用户画像。黄金礼品中的送礼者与收礼者、本系统中的一级代理与 C 端用户等角色必须拆开处理。核心画像卡须在生成三个 IP 策略方向前由用户确认或修正；后续数据只能提出画像修订建议，不能静默覆盖用户已确认的版本。

### 8.3 从用户画像进入内容世界

画像确认后，系统才研究这个人真实生活或经营环境中会反复发生的事件、相互影响的人、各自的欲望与损失、必须作出的选择，以及这些选择怎样连接产品。系统据此寻找可持续的叙事发动机，例如身份变化、隐藏机制、利益冲突、小人物与大趋势、承诺代价和关系误解。

### 8.4 本系统自己营销自己

平台建立一个平台所有的内部 IP 项目，由第 4.3 节定义的平台内容运营负责人操作，使用与 C 端项目相同的访谈、画像确认、三策略选择、研究、选题、营销叙事、制作、审核、人工发布、数据回收和复盘链路。该项目至少拆分三个受众轨道：一级代理、二级代理和 C 端用户；系统不得把渠道购买者、渠道经营者和最终使用者混成同一个画像。

三个轨道共用一个项目级总 IP 策略：系统先生成三个总方向，每个方向都必须包含三个轨道的适配说明，平台内容运营负责人只作一次三选一。选定后再为每个轨道冻结一份轨道方案，分别规定内容承诺、信任证据、栏目组合、转化动作和禁用表达。轨道方案不能互相借用数据，也不能改变总策略；如果某个轨道需要完全不同的人物身份或账号承诺，应另建一个平台 IP 项目并重新走三选一，而不是在同一项目内分裂定位。

自营销内容只能使用平台自身真实能力、公开资料、内部实测和取得明确授权的客户案例，不能读取或暗用客户私有项目。该项目不得绕过事实、权利、AI 标识、营销风险或媒体质检闸门，也不得拥有硬编码的高分、特殊提示词或专用宣传模板。它既是获客项目，也是持续的内部实战测试；发布结果要进入独立项目记忆，不能污染任何客户项目的画像、基线或经验。

### 8.5 候选策略比较

候选策略按以下维度比较：

- 是否准确对应已确认的核心画像和购买关系。
- 是否持续有真实事件发生。
- 商家是否拥有第一手素材或可靠研究能力。
- 是否有鲜明人物和矛盾。
- 是否可连续生产一年以上。
- 是否适合目标平台。
- 是否保持业务联想。
- 是否真实、合规且可以拍摄或生成。

## 11. 研究、营销与真实性平衡

系统把内容分为四类：

1. **个人判断**：可以尖锐，明确属于立场。
2. **商家经验**：必须真实发生，并表明是自身观察。
3. **公共事实**：后台核实，成片不要求展示论文式引用。
4. **重大因果、功效、收益和政策主张**：需要更强依据，不能靠修辞越过。

研究事实账本记录陈述、来源、日期、适用范围、类型、冲突来源、可信程度和重新核实时间。

上述内容类别之外，每一条会影响画像、策略、选题、叙事或发布判断的陈述还必须标记一种认识状态：用户原话、外部证据、模型解释、创意假设、未知或真实结果。模型解释和创意假设不能静默升级为事实；未知不能写成零、否定或模型自行补齐的经历、能力、案例、资源和地域判断。

允许选择性叙事、延迟揭示和观点先行，但整个内容结束后不能留下虚假事实。真实可识别人物不得因悬念设计受到不必要污名。

## 12. 发布预测和学习闭环

### 12.1 发布前预测

记录策略版本、选题、营销结构、形式、平台、主要实验变量、预期指标变化、预期评论、失败原因和信心等级。

一次内容原则上只设置一个主要实验变量。预测冻结后只能追加说明，不能篡改。

### 12.2 数据回收

用户手动提交链接、表单或后台截图。系统保存原始截图和提取结果；识别不确定的数字必须由用户确认。

用户必须同时登记实际发布版本。复盘以最终成片、标题、正文和发布时间为准，不能用 Agent 原稿解释用户修改后的内容表现。

按平台分别保存 T+1、T+3、T+7 的播放/曝光、观看、完播、互动、收藏、分享、涨粉、主页访问和可获得的商业指标。

- 注意力：是否点开或停下。
- 留存：开头承诺是否被内容接住。
- 共鸣：是否互动、收藏、转发和表达立场。

经验依次经过：单次观察、候选假设、多次重复、项目规则、反例降级。策略调整只能形成用户待确认的新版本。

## 13. 创作点与代理结算

### 13.1 线下收款

- 一级代理线下向平台付款，平台确认后充值创作点。
- 二级代理线下向一级代理付款，一级代理确认后划拨创作点。
- C 端线下向所属代理付款，代理确认后充值创作点。
- 付款截图仅为凭证，不能自动触发充值。
- 首版不接在线支付，不做自动分账。

### 13.2 两本账

1. 现金订单记录：谁向谁支付了多少；线下真实金额未录入时只能显示估算。
2. 创作点账本：发行、购买、划拨、冻结、结算、释放、补偿和退款。

创作点账本采用追加式分录，禁止修改旧记录。余额是可重算的汇总，不是唯一事实。

余额不得为负。下级充值或代理间划拨必须在一个数据库事务中同时扣减上级、增加下级并写入关联分录；并发请求不得造成超额划拨。未使用额度向上退回时走反向申请和审批，不能直接修改余额。

### 13.3 生成扣费

```text
估算最高费用
→ 冻结创作点
→ 创建生成任务
→ 记录供应商实际消耗
→ 成功结算
→ 未使用部分释放
```

冻结、创建任务和写入 outbox 必须在同一个 PostgreSQL 事务中完成。系统自身错误导致的重做不向用户重复收费；用户主动要求新版本或额外镜头视为新任务。

平台、代理和 C 端分别具有单任务、单日和单月创作点上限。达到上限时暂停新付费任务，不能在后台继续产生未展示费用。

平台自营销项目使用独立内部成本中心，不进入创作点钱包。其流程为：按人民币分估算最高成本，创建 `InternalBudgetHold`，同时创建生成任务和 outbox；任务结束后按 `ProviderCostEntry` 结算实际成本并释放余额。供应商原生用量和账单币种同时保留，人民币换算引用当时的成本价格版本。该流程不消耗可转售给代理或 C 端的创作点，也不计为代理收入；内部项目同样受单任务、单日和单月预算上限约束。

### 13.4 价格权限

- 平台设置一级进货价、最低转售价、能力消耗价和活动规则。
- 一级代理设置二级进货价和直属 C 端售价。
- 二级代理设置直属 C 端售价。
- 价格变更只影响未来订单。

## 14. 权利、隐私和合规

### 14.1 数据地域

- 首版用户资料、人物资产、数据库和对象存储均在中国大陆。
- 首版不由系统向 TikTok 或境外服务发送个人信息和人物素材。
- 用户自行下载成片并发布海外平台。

### 14.2 数字身份授权中心

肖像许可、声音许可和敏感个人信息同意分别记录，不使用一个笼统勾选框替代。记录授权人、用途、平台、项目、地域、期限、次数、商业使用、是否允许建模、是否允许复用、是否允许转交火山处理、撤回和历史成片处理规则。

声音或肖像本人应通过可验证方式直接确认高风险授权。撤回后停止新生成并冻结相关数字资产。

### 14.3 未成年人

- 注册用户限定十八周岁以上。
- 上传儿童素材必须记录年龄和监护人授权。

- 自动提醒隐藏学校、住址、定位、车牌、作息和医疗信息。
- 代理商默认不能查看儿童素材。

### 14.4 AI 内容标识

- 文本、图片、音频、视频和虚拟场景进入统一标识流水线。
- 数字人口播和 AI 情景剧添加显式标识。
- 文件元数据写入生成合成属性、服务信息和内容编号等隐式标识。
- 每次转码、加字幕和导出后重新检查标识。
- 首版不开放去除显式标识的例外功能。

### 14.5 上线前外部确认

产品在外部确认完成前也必须具备输入审核、生成结果审核、用户申诉、公众投诉、违法滥用处置、内容删除和审计留存功能。模型名称、模型备案信息、本应用登记或上线编号及适用功能进入“模型合规注册表”，并按主管要求在产品显著位置展示。

以下事项必须在公开商业上线前由律师、客户经理或主管部门形成书面结论：

- 应用登记、算法备案、安全评估的具体组合。
- ICP 备案之外是否需要增值电信业务经营许可。
- 平台是否构成广告经营者及广告档案义务。
- 数字人、声音复刻和真人人像的企业商业授权。
- 代理预充值模式的合同、税务、发票、消费者权益与层级销售风险。
- 网络安全等级保护定级。
- 未成年人商业数字分身和亲子带货的具体边界。

## 15. 火山模型与基础设施

### 15.1 能力注册表

后台保存能力、完整模型 ID、生命周期、账号可用状态、输入输出模态、参数范围、价格版本、安全版本和回归测试结果。

新模型不能自动进入生产。必须先运行固定测试集，再由平台管理员切换。Retiring 模型提前迁移；Shutdown 模型禁止创建新任务。

### 15.2 媒体结果转存

Seedream、Seedance 和 TTS 返回地址均视为临时地址。成功后立即下载、校验 checksum、验证可解码性并转存私有 TOS，记录模型版本、提示词、参考素材、费用、审核结果和用户选中版本。

### 15.3 推荐部署

优先在华北 2（北京）主地域部署；购买前确认目标规格和各产品地域可用性。

- 普通 APIG 作为 API 入口。
- VKE 跨可用区运行应用和 Worker。
- VCI 承担突发 FFmpeg 和媒体后处理任务。
- PostgreSQL 一主一备作为主数据库。
- Redis 主备作为缓存和协调层。
- RocketMQ 多可用区承担任务通知、重试和死信。
- TOS 私有桶、版本控制和必要的跨地域复制。
- CDN 只分发允许公开缓存的成片；私有素材使用短期预签名访问。
- TLS、云监控和托管 Prometheus记录日志、指标和告警。

### 15.4 实施技术选择

- Web 前端：TypeScript、React 和 Next.js，提供 C 端、代理和平台后台三套路由。
- 核心 API 与 Agent Worker：Python、FastAPI 和 Pydantic，使用同一领域模型与结构化 Agent 协议。
- 数据访问与迁移：SQLAlchemy 和 Alembic；账本相关写操作必须使用数据库事务和唯一约束。
- 媒体处理：FFmpeg 独立 Worker，所有命令从受控参数生成，不拼接用户原始命令字符串。
- API 契约：OpenAPI；前端类型由契约生成，避免前后端字段漂移。
- 测试：Pytest 负责领域、账本、Agent 契约和故障恢复；Playwright 负责端到端用户流程。
- 部署：容器镜像运行于 VKE；高波动媒体后处理任务可调度到 VCI。
- 首版不引入独立向量数据库；项目检索先使用 PostgreSQL 结构化字段和全文检索。需要语义召回时，在同一数据边界内增加火山向量化能力，并经过单独性能测试。

## 16. 失败恢复和审计

### 16.1 通用错误信息

每次失败都向用户说明：发生了什么、哪些内容已保存、用户需要做什么、系统将如何继续。

### 16.2 必须可恢复的异常

- 模型、搜索或供应商暂时不可用。
- 网页无法读取。
- 上传文件损坏。
- AI 输出不符合结构。
- 用户重复点击。
- 两人或两个任务同时修改同一对象。
- 截图数据识别不确定。
- 回调重复、乱序或丢失。
- 媒体成功但临时链接即将过期。
- 生成内容安全拦截。
- 数据库、队列、文件或单可用区短暂故障。

所有任务可从最近成功步骤继续，不要求用户重新完成访谈或整条视频重新生成。

### 16.3 删除与恢复

- 普通删除进入回收站。
- 永久删除需要二次确认。
- 数据库、对象存储、模型服务状态和缓存按照删除计划清理。
- 备份不替代用户删除权；备份中的数据按保留周期自然过期。

### 16.4 审计

记录操作者、Agent、提示词/规则版本、模型版本、输入来源、修改、审核、费用、重试、访问授权和结果。日志隐藏密钥、证件、地址、音色训练素材和其他敏感内容。

### 16.5 备份与灾难恢复

- 生产目标为恢复点不超过一小时、核心服务四小时内恢复。
- PostgreSQL 持续备份并定期恢复到新实例验证。
- TOS 开启版本控制；关键账本校验文件和必要媒体执行异地复制。
- 每月至少完成一次数据库或关键文件恢复演练，每季度完成一次完整灾难恢复演练。
- “已打开备份开关”不构成验收，必须保存实际恢复记录和校验结果。

## 17. 测试与上线标准

### 17.1 测试层级

1. 确定性代码单元测试。
2. Agent 输入输出结构和状态契约测试。
3. 五类固定项目情景测试。
4. 冻结方案后才揭晓的跨行业 unseen 测试；五类固定项目不得作为生产 Prompt、Skill 示例、检索金答案或关键词补丁。
5. 运营和编导双人盲评。
6. 媒体质量、连续性和授权测试。
7. 账本随机交易和对账测试。
8. 故障注入与恢复测试。
9. 权限越权、提示词注入和隐私测试。
10. 真实商家封闭发布测试。

### 17.2 营销质量

每个选题生成普通通用 AI 对照版和本系统版，由至少两名有经验的运营/编导盲评：目标画像匹配、观看欲望、兑现程度、人物情境、观点、人格一致性、可拍摄性、业务连接和标题党风险。

固定案例库中，本系统版本至少在 70% 的盲评配对中优于通用 AI 对照版；存在虚构事实、不可拍摄或人格明显不符的结果直接判为失败，不得用其他维度高分抵消。

### 17.3 严重错误零容忍

- 项目或商家数据泄漏。
- 越权访问。
- 篡改冻结预测或历史数据。
- 把虚构标记为真实。
- 未经授权使用肖像、声音或儿童素材。
- 重大商品事实、收益、医疗或政策虚假主张。
- 重复扣点、重复退款或账本不平。
- 系统失败却显示成功。
- AI 标识在最终导出中丢失。

### 17.4 工程验收基线

- 非 AI 普通接口在正常负载下 95% 请求两秒内完成。
- 长任务三秒内返回可查询的任务编号和预计状态，不阻塞网页请求。
- 固定测试集中所有关键结构化输出在有限重试后成功率达到 99% 以上。
- 对至少 10,000 组随机充值、划拨、冻结、结算、失败和退款序列进行账本不变量测试，差异为零。
- 重复、乱序回调测试中不得重复扣点或推进错误状态。
- 数据库恢复、单可用区故障和异地关键文件恢复均完成真实演练。

### 17.5 封闭 Beta

首批覆盖四类客户项目和一个平台自营销项目，测试周期至少六周，每个项目至少发布十二条内容，总量不少于六十条。平台自营销项目中，一级代理、二级代理和 C 端用户三个受众轨道各至少发布三条内容。每个项目完成完整入驻与画像确认；每条内容保留画像版本、策略关联、制作版本、发布记录、T+1/T+3/T+7 数据和复盘。

四个客户项目的核心结果指标是内容相对各自账号历史匹配基线的播放、完播和互动表现。进入公开 Beta 前，至少三个客户项目的平台内标准化内容表现中位数提升 15% 以上，且没有通过虚假承诺、重大争议或不可持续投流换取该结果。辅助目标为推荐选题采纳率达到 60%，最终脚本无需结构性重写的比例达到 70%。

平台自营销项目不计入上述“三个客户项目达标”数量。一级代理、二级代理和 C 端用户三个受众轨道分别冻结目标与基线，分别统计曝光、主页访问、有效咨询、代理申请、注册或试用等业务行动；没有历史匹配基线时只登记冷启动结果，不宣称提升。封闭 Beta 期间，每个轨道至少产生一个经人工去重并确认来源的有效业务行动，否则自营销实战检验不通过。任一必需指标未达到时继续封闭测试，不以用户主观好评替代。

## 18. 分阶段建设

该系统不得写成一个单体实施计划。拆为六个可独立验收的子项目：

### 子项目 1：平台基础与可信账本

账户、平台内部运营权限、固定代理层级、C 端多 IP、创作点账本、内部成本中心、价格版本、模型注册表、任务状态、TOS 和基础审计。

### 子项目 2：IP 内容智能

五个商业根问题、访谈、项目档案、购买关系、版本化用户画像、三个策略方向、研究、对标、选题、营销叙事、编导、人格校准、事实审核、本系统自营销工作流和抖音/小红书适配。

### 子项目 3：生成式媒体工作室

Seedream、Seedance、标准 TTS、故事板、镜头任务、低清预览、高清生成、后期、字幕、AI 标识、媒体质检和成片交付。

### 子项目 4：发布与学习闭环

发布前预测、人工发布记录、截图/表单数据回收、评论洞察、复盘和项目记忆。

### 子项目 5：代理运营后台

线下收款记录、额度划拨、价格权限、代理客户管理、异常退款、停用迁移和对账报表。

### 子项目 6：数字人 Beta 与公开上线

生产账号 PoC、肖像/声音授权中心、声音复刻、真人人像资产、传统数字人 Beta、备案登记、等保、合规审核、灾备和公开 Beta 上线闸门。

### 推荐第一条端到端切片

## 20. 规格确认补充条款（2026-08-25）

本节记录初版规格完成后的实现边界。20.1 至 20.4 形成用户确认的 v1.1；20.5 将用户要求的前六轮审计结论固化为 v1.2 实施与验收护栏。v1.2 不新增客户类型、销售层级、能力承诺或第七个产品子项目；后续计划、代码和验收报告若与本节冲突，以本节为准并提交显式变更记录。

### 20.1 所有行业共用的内容世界扩展

当且仅当五个商业根问题都已达到可用状态，系统才在生成选题前运行服务端固定的六视角内容世界扩展：

1. 对象分类与细分。
2. 历史与文化。
3. 地理与环境。
4. 生产与流通。
5. 人物、关系、选择与代价。
6. 购买者、使用方式与决策。

这六个视角适用于水果、黄金礼品、TikTok 直播公会、本系统自营销、信息不足宝妈及未来合法行业，不是水果专用提示词。扩展结果只能是待核验的研究问题和检索方向；地域趋势、历史故事、产业判断及人物经历在进入选题事实底座前必须取得可追溯来源，不能因模型表达肯定而被当成事实。

### 20.2 选题后的主体风险确认

用户选中一个具体选题后、生成营销叙事前，必须确认该选题是否涉及真实人物、是否可识别、是否含严重指控、有哪些私有证据，以及结尾必须恢复哪些足以改变公众判断的真相。主体及风险键由服务端根据当前已选选题推导，前端不能自报另一个主体绕过审核；确认记录必须同时绑定该不可变选题卡 ID 与服务端主体键，两个不同选题即使涉及同一主体也必须分别确认，不能继承或覆盖彼此的确认。涉及真实人物时必须引用项目内已验证的私有来源，涉及可识别人物和严重指控时必须填写关键恢复真相。

该确认只追加一个不可变项目档案版本：身份、产品或服务、受众、现实限制、策略及其他业务字段必须逐项原样复制，只替换当前选题对应的风险声明。正常 `ACTIVE` 项目继续保持 `ACTIVE`，不触发重新定位；同一确认精确重放返回原版本，内容改变才生成下一版本。当前选题没有精确匹配的确认时，营销叙事入口保持关闭。

### 20.3 营销张力与可避免污名的固定回归

营销可以使用选择性叙事、观点先行、悬念和延迟揭示，但最终留给观众的信念必须真实且范围准确。对于真实且可识别的人，系统不得为了开头张力先制造足以造成可避免污名的严重结论，再依靠结尾反转免责；这条规则由服务端根据主体声明、私有证据和研究事实机械判断，模型即使谎报“无风险”或“审核通过”也不能覆盖。

固定回归案例是：“这个男人弄死了他养了十年的小狗”作为先行定罪，而完整事实是小狗患有绝症、持续痛苦，主人只能选择安乐处置以解除痛苦。若主人可识别，该结构必须阻断。只有去标识或明确披露为虚构/重构时才可采用延迟揭示，并且结束前必须完整恢复“绝症”“持续痛苦”“处置目的为解除痛苦”三项真相；少一项、只在说明区补充或让观众最终仍相信主人残忍，均不得发布。

### 20.4 Plan 02A 的归属

“供应商请求持久化与最终账单对账”是子项目 2 的强制发布安全加固，编号为 Plan 02A，仅控制真实火山方舟 Responses 与 Web Search 的启用条件。它不增加产品能力边界，不作为子项目 7，也不改变本规格第 18 节的六子项目结构。未完成调用前持久化、供应商完整请求清单导入、最终账单逐笔匹配、零调用证明和杀进程演练前，生产环境必须在读取密钥和创建 HTTP 客户端之前拒绝开启这两项真实能力。

### 20.5 前六轮系统审计护栏

前六轮系统的完整证据、弃用原因和复用清单，以 docs/architecture/2026-08-25-legacy-six-version-decision-memory.md 为当前决策记忆。本补充不增加产品板块，而是约束实现方法：

- 五个商业根问题是可由已有资料填充、允许显式未知的业务就绪状态，不是固定逐题问卷；只追问当前最决定下一步的一项未知。
- 六视角扩展只能生成候选研究问题，不要求六类齐全，不按分支数量选择内容根，也不能成为硬编码的行业答案。
- 内容世界、命名人物或事件的证据发现、具体选题、表现形式和商业承接分层处理；商业回流不能反向决定内容根。
- 五个固定项目只用于回归和盲评，不能进入生产提示词、Skill 示例、检索上下文或关键词规则；泛化结论必须另有冻结 unseen。
- 新增 Agent、Skill、硬闸门、运行时、状态表或长期上下文前，必须先记录一个真实 held-out 失败、未改基线、最小候选、质量/事实/Token/时延/成本对照和删除路径。
- 权限、版本、父级、哈希、确认、预算、调用次数、幂等、扣费和供应商对账由代码执行；模型只能建议。
- 能力状态分别标记为代码存在、机械合同通过、真实调用可达、业务盲评通过、真实发布复盘通过，低级状态不能替代高级状态。
- 当前系统永久不依赖或调用 map-marketing-content-world；相关旧材料只可作为历史证据。
