### 3.1 重建 V1：外壳与插件式 Marketing OS

可核实材料：

- 项目路径：/Users/yangyucheng/projects/marketing-os-desktop。
- 早期能力曾分散在桌面 React/Electron、局部服务和 Hermes 插件目录。
- 2026-06-29 会话：/Users/yangyucheng/.codex/archived_sessions/rollout-2026-06-29T23-10-26-019f13ee-84ed-7cb1-87a5-4f5dc9951cbc.jsonl。
- 用户明确指出“说你好却分析营销数据”，并要求它必须是真智能，而不是套壳、只完成某些步骤的伪智能。
- 用户随后明确要求删除原 Hermes 安装、下载源码直接适配，并清理所有不符合新台账和资料库的实现。
- 源码重建基线提交：e550ec2d7，2026-06-29。

被替换原因：

1. 展示层先于 Agent 行为成立。按钮、预填提示词和页面可以工作，但不能证明 Agent 理解了当前任务。
2. 桌面外壳、插件、局部服务和 Hermes 自身分别拥有能力，形成事实上的多所有者。
3. 账号登录、浏览器会话、平台采集和真实服务验证不够顺滑，用户看到的是技术拼接而不是连续经营体验。
4. 对话意图路由错误是业务级失败，不是一个文案小问题。

应保留：

- 长期账号经营，而不是一次文案生成。
- 学习用户偏好、账号适配、平台差异、拒绝原因、失败恢复和发布结果。
- 账号隔离的浏览器身份和连续任务上下文。
- 用户始终知道“我在哪里、处理哪个对象、产物去了哪里”。

禁止复用：

- 外部插件加薄桌面壳作为第二业务大脑。
- 依靠按钮预填提示词冒充 Agent 主动执行。
- 前端显示“已完成”而后端只存在 mock、局部服务或未验证调用。

### 3.2 重建 V2：Hermes 原生单运行时重建

可核实材料：

- 同一 Marketing OS 仓库中的源码重建阶段。
- 代表提交：144c665b5 架构与产品台账；b993ae3e4 生命周期、学习、预检和内容引擎；abf3ae7 原生产品 fork；b728f5e6 原生运行时基线；12a6e75b 原生桌面切换；104bb747f 产品拥有自己的运行时与发布；e772977a4 重塑 Hermes 外壳；6fcba347f 原生营销流程端到端。
- 本轮没有找到独立命名为“第二版”的冻结目录，因此边界属于重建。

被替换原因：

1. 单运行时方向是正确的，但“模块存在”没有自动变成“Agent 会正确调用并交付业务产物”。
2. 账号、资料、知识、选题、预演、内容、发布、回执和学习不断增加，缺少一条可以用真实客户问题判断成败的最短纵切。
3. 工程进度容易按模块、接口和测试计数，业务进度却没有按任务解释、事实绑定、产物可用性和真实结果计数。
4. 后续重构持续处理“新增底层和知识没有串起来”“什么时候收口”的问题，说明此轮并未形成稳定的决策主线。该项是由后续直接反馈和替代关系推断，证据等级为 B，不写成独立版本的正式弃用声明。

应保留：

- 一个原生 Agent 运行时拥有账号身份、任务、记忆、工具、状态和产物。
- 预测、发布回执、复盘和恢复是一条长期控制回路。
- 真实证据、用户授权和账号边界属于底层能力。
- 每个业务产物有稳定 ID、版本和来源。

禁止复用：

- 先建齐所有模块，再期待 Agent 自己把它们串起来。
- 以“接口已接通、测试已通过”代替真实营销任务验收。
- 在没有一条短业务纵切时继续扩展知识库、图谱、平台或 Worker。

### 3.3 重建 V3：全周期经营与“超级编导”扩张

可核实材料：

- Marketing OS 代表提交：7e72b1807 原生产品工作台；0d39b8d74 收拢生产闸门；9b98431db 认识论权限；5dbae84af 多平台生产预检；71d8b8dfa 成本感知多模态方向；06674e820 超级编导知识闭环。
- 关键会话：/Users/yangyucheng/.codex/archived_sessions/rollout-2026-07-17T04-43-20-019f6cab-6787-7412-aa14-40628a9b8797.jsonl。
- 用户实际测试发现：对话只能读取一个平台；视频依赖图文先出脚本和分镜；素材管线没有真正运转；Agent 与 Hermes 仍不像完全一体。
- 用户明确指出视频不是图文的下属，并要求重新审视多 Agent/Harness 架构。
- 用户还发现付费调用造成意外费用，追问系统边界；素材检索、渲染、剪辑和“超级编导”称号与真实可达能力不一致。
- 最后暂停并转向审计字节开源 Agent 底座。

被替换原因：

1. 全周期目标正确，但同时推进多平台采集、预演、图文、视频、素材、发布和学习，范围超过真实可验证能力。
2. Marketing Agent、Hermes、视频工作台和多个生产角色仍存在重复权威与状态。
3. 媒体链顺序错误。正确顺序应是选题确认后写稿或剧本，再形成镜头计划，再按镜头找或生成素材；旧链曾按标题先找素材。
4. 固定多 Agent 和“超级编导”命名制造了能力错觉，角色数量不等于业务判断质量。
5. 自然语言预算和普通重试无法保护付费调用，造成真实成本风险。
6. UI、运行时和业务主线多次重构，改动面越来越大，真实客户产物反而难以验收。

应保留：

- 同一选题可以独立进入图文、视频或其他表现形式，视频不从属于图文。
- 选题 → 稿件/剧本 → 镜头 → 素材 → 生成/剪辑 → QA 的正确因果顺序。
- 草稿、失败恢复、素材权利、成本、连续性、成片 QA。
- 平台差异和发布前预测，但只能在真实证据基础上使用。

禁止复用：

- 固定多 Agent 顾问团、投票或角色齐全才算完成。
- 第二套视频总控、DAG、数据库或状态机。
- 未经预算冻结和代码限额的真实供应商调用。
- 把能力名、结构化 JSON 或模拟视频当作真实制作能力。

### 3.4 V4：DeerFlow IP Agent

正式路径与提交：

- /Users/yangyucheng/Documents/第四版营销系统
- 冻结提交：58f4e0c9
- 当前产品台账：docs/IP_AGENT_PRODUCT_LEDGER.md
- 迁移总台账：/Users/yangyucheng/Documents/Codex/2026-07-21/ni/outputs/IP智能体建设总台账.md

本轮做对了什么：

- DeerFlow 是唯一大脑，不叠 Agent TARS、VeADK、Coze 或旧视频系统作为第二运行时。
- Subject 是人物、品牌、产品或组织的单一真相源；账号、受众、内容和视频是投影，不是第二份身份真相。
- 建立 Owner → Subject → Program/Work → Direction → Script → Production → Artifact → Publication → Observation → LearningDecision 的不可变谱系。
- 严格区分用户事实、外部证据、推导假设、创作虚构和执行回执。
- 保留精确版本、哈希、幂等、权利、恢复和“缺失不等于零”。
- 明确“工程接通”不等于真实模型行为、供应商成片或传播效果成立。

被替换原因：

1. Personal-IP 早期主要靠前端和完全 mock 的 Playwright 场景，真实后端 E2E 没有相称覆盖。
2. 为了稳定业务输出，逐步增加编排闸门、业务语义硬闸门、固定叙事访谈、SOUL 和 Writer Brain 巨型控制层。
3. 硬合同把创意、事实、交易、发布和叙事结构混在一起，局部错误会迫使整条链重跑。
4. 导演核真实试验曾耗 20,171 Token、270 秒；它能纠正部分本体，却没有形成可用的 IP 外环。后续因果桥也暴露“商业目标变人物目标”和“产品沦为可替换软植入”。
5. 平台数量、模型接入、HLLM、视频双模式等大量“已接通”项目没有都经过真实业务和真实供应商验收。

应保留：

- 单一 Subject 真相源和不可变内容谱系。
- 事实、证据、假设、虚构、回执分层。
- 哈希、版本、Owner、幂等、恢复、权利与授权。
- 产品若不影响故事因果，就退出故事；不能做可替换软植入。
- 非叙事内容不强迫讲故事。

禁止复用：

- 固定编排闸门、业务语义硬闸门、旧语义层和固定叙事访谈。
- 整包迁移 Writer Brain、SOUL、旧 middleware 或第二状态系统。
- 把 research 目录、mock E2E 或代码连接状态注册成现役产品能力。

### 3.5 V5：营销脑与内容世界实验

正式路径与提交：

- /Users/yangyucheng/Documents/ChatGPT/第五版营销系统
- 冻结提交：3ee135f7
- 冻结文档：docs/mcn-incubation-v5/V5-FINAL-SNAPSHOT.md
- 试验总账：docs/mcn-incubation-v5/LEDGER.md

本轮做对了什么：

- 将“内容世界”与“表现形式”分开：先决定长期讲什么，再决定真人、数字人、剧情、口播、图文等怎样呈现。
- 区分经营容器、真正业务对象、词法主语、修饰词、买方用途和行动主体。
- 认识到对象本身可能已经是完整内容世界，不能一律向上抽象。
- 命名人物、事件、作品不能从类别地图自动推出，必须单独 discovery 和取证。
- 采用预注册、冻结门、seen/unseen 和对照实验，留下了高价值失败证据。
- 单一 Lead 最终裁决优于固定顾问团。

被替换原因：

1. 固定三顾问加 Lead 一次消耗 17,834 Token、159 秒；单 Lead 只需 4,419 Token、51 秒，而且多 Agent 反而增加无依据事实和模板。
2. 固定审计员收益不稳定，既增加成本，也会误判创意。
3. 长 Lead 提示词、固定阶段、固定候选数、固定问题数、评分闸门和实验闸门逐渐成为第二套程序。
4. 水果回到“最懂水果的人”和挑选、时令、品质；宝妈产生刻板人物模板；模型还会虚构预算、资质、案例、仓储和配送。
5. 七轴地图即使很丰富，也不能证明根选择正确；错误根同样能生成完整地图。
6. seen 4/4 不能证明泛化。雪茄 unseen 即使消耗 42,340 Token 仍全链失败。
7. 模型先猜人物或事件、再搜索验证，无法找回它一开始根本没有想到的实体。
8. 行业金答案、关键词补丁和示例逐步污染泛化评估。

应保留：

- 单一 Lead 最终权威，子 Agent 只做有边界的证据、媒资和独立审计。
- 六类认识状态：用户原话、外部证据、模型解释、创意假设、未知、真实结果。
- 内容世界与表现形式分离。
- 交易角色与词法主语分离。
- 先阅读证据，再生成命名选题候选。
- 预注册、冻结评测和跨行业 unseen。

禁止复用：

- 累积长提示词和完整 semantic/map 运行时。
- E28 至 E40 失败候选。
- 固定阶段、候选数量、问题数量、评分门、实验门和工具轨迹。
- 黄金礼品、水果等行业金答案或关键词补丁。
- 把五个当前案例放进生产 Prompt、Skill 示例或检索上下文。

### 3.6 V6：薄 Agent、Skill 与权限重建

正式路径与提交：

- /Users/yangyucheng/Documents/ChatGPT/第六版营销系统
- 当前可引用提交：326eab3b
- 决策与证据：docs/content-intelligence-v6/LEDGER.md
- A150 存在未提交工作树，只能作为最后清理证据，不可直接复制代码。

本轮做对了什么：

- 清洁迁移：第五版保留为失败证据和评测历史，不作为代码模板。
- 薄 Agent 身份、按需 Skill、服务端权限、一次性确认动作。
- 方向机会与账号经营策略分离。
- 行业知识只能提供有理由的软建议；确定性代码只管父级、版本、权限、预算和关系。
- 自然语言不能约束工具预算，必须由代码在调用前原子预占。
- 真实供应商创建最多一次；submission_unknown 不自动重试；保留 provider ID、成本、QA 和产物哈希。

被替换原因：

1. 黄金礼品的“商业回流”被编译为内容根硬约束，反而把“礼、人情往来”压回黄金产品。商业承接应在内容世界形成之后处理。
2. 清空记忆仍选择错误根，证明问题不是记忆污染，而是 Agent 收敛和任务解释错误。
3. 改用“最大有效内容世界”后虽能选对根，却会为了满足行动链虚构命名事件。
4. 行业 Skill 形成默认答案、确定性覆写、提示词禁支和字符串拒绝四层硬控，完整重走 V4。
5. 五次黄金真实端到端共消耗 658,269 Token、75 次模型调用，仍不能稳定同时交付人物/事件选题和可拍草稿。
6. 一次运行曾达到 57 个工具、159,506 Token；24 个 Skill 摘要和 17 个工具路由让“薄内核”实际变成顾问报告系统。
7. TikTok 直播公会回归虽降为一次调用、4,616 Token、约 56 秒，业务仍完全答错：没有受众、定位、内容世界、表现形式和可拍选题，反而输出资质、主播招募、七天和九十天运营并编造数字。
8. 自然语言“一次搜索、不重试”仍跑到 66,000 至 83,000 Token；加代码预算后仍捏造经历、能力和区域事实。
9. 12,688 个测试通过只能证明权限、状态和谱系，不证明营销业务质量。

应保留：

- 薄身份、按需能力、服务端权限和显式用户动作。
- 代码级工具预算、付费调用 at-most-once、供应商对账。
- 内容机会与账号策略分离。
- 用户画像和产品自有资料必须有来源、可纠正、可版本化。
- 完成定义必须同时满足：任务解释正确、产物可用、重要未知显式。

禁止复用：

- ContentRootLab、全局业务 attention、根选择硬门和行业 Skill 标准答案。
- 用 Prompt 管权限、确认、调用次数、预算或持久化。
- Tool/Skill 越多越像 Agent 的思路。
- 用测试数、低 Token 或一次成功调用宣称业务脑成立。

## 4. 六轮共同暴露的根因

共同根因不是“模型不够聪明”，也不是“少一个模块”。主要矛盾是 Agent 系统设计：

1. 任务解释错误。用户问“怎么起号”，系统可能回答行业 SOP，而不是识别受众、定位、内容世界、形式和首条可拍选题。
2. 权威不唯一。Lead、工作流、Skill、语义根、审计员、视频总控分别在作最终决定。
3. 软判断被编译成硬规则。某个案例有效的思路被写进 Prompt、关键词、评分或代码后，破坏跨行业泛化。
4. 业务、事实、创意和机械控制混层。创意判断需要模型，权限、版本、预算和幂等必须由代码负责。
5. 模块先行，纵切滞后。系统有很多能力名，却不能稳定完成一个真实任务。
6. 技术成功冒充业务成功。代码接通、测试全绿、JSON 合法、Token 下降都不代表营销答案有用。
7. 固定多 Agent 放大成本和幻觉。角色越多并不自动产生更好的总编判断。
8. 真实成本边界出现得太晚。付费调用、重试和进程崩溃必须在业务实验前就有确定性控制。
9. 案例答案污染评测。黄金礼品的“礼”、水果的“地理历史”一旦成为提示词答案，就无法证明系统会泛化。
10. 每次重构只增加、不删除。没有候选淘汰和复杂度预算，最终所有失败机制都留在上下文里。

## 5. 当前项目必须继承的十条护栏

### LG1 单一总编权威

一个 Lead/总运营编导拥有最终业务判断。其他 Agent 仅按需提供证据、事实核验、媒资、风险或独立盲审，不投票决定定位，不拥有第二套持久状态。

### LG2 五问是业务状态，不是固定问卷

五个商业根问题必须都有当前状态，但不强迫用户按固定顺序逐题回答，也不把未知伪造成答案。已有资料可以自动填充；信息不足时只追问当前最影响下一步的一个问题。未知允许保留，并显示会影响什么。

### LG3 内容世界、具体选题、表现形式、商业承接四层分开

下列是逻辑依赖，不是必须线性执行的流程。Lead 可依现有证据跳过、并行或回退，但不得把后层结论冒充前层证据：

1. 确认业务主体、交易角色和受众。
2. 形成内容世界候选和待研究问题。
3. 对命名人物、事件、作品和事实单独检索取证。
4. 形成具体选题。
5. 决定真人、数字人、情景剧、图文、口播等表现形式。
6. 检查内容如何建立业务联想和推动行动。

商业目标参与最终适配和验收，但不得反向强迫内容根回到产品工艺。对象本身若已是完整世界，也不得为了显得高级而强行向上抽象。

### LG4 六类认识状态不可混写

所有重要陈述必须属于且只能属于以下一种：

- USER_FACT：用户明确提供的事实。
- EXTERNAL_EVIDENCE：可回到来源的外部证据。
- MODEL_INTERPRETATION：模型对事实或证据的解释。
- CREATIVE_HYPOTHESIS：待验证的营销角度、故事假设或钩子。
- UNKNOWN：当前不知道或证据不足。
- ACTUAL_RESULT：真实发布、供应商、成本或用户行为回执。

创作可以用春秋笔法、延迟揭示和观点先行，但不能把创意假设升级成事实。若前半段会让观众对可识别真人形成严重错误道德判断，同一内容必须完整恢复关键反事实；无法恢复时阻断发布。狗安乐死案例继续作为固定高风险回归。

### LG5 普通聊天不等于不可逆授权

普通聊天只是上下文，不自动授权花费、对外发送、发布、永久删除或受权利约束的真人素材使用。在用户已授权的 Mission 内，Lead 可自主选择、锁定、回滚或比较可逆的方向、TopicCard、脚本和制作版本，并保留 diff 与 undo。只有改变主体定位/业务目标的重大方向，或真正执行不可逆动作，才要求用户对精确 Artifact/ID 进行确认。授权只继承其明示的 Subject、Artifact、用途和范围。

### LG6 确定性边界只能由代码执行

以下事项不得依赖提示词：

- Owner/租户隔离。
- 权限、授权和隐私。
- 版本、父级、哈希和不可变谱系。
- 预算、调用次数、at-most-once 和重试。
- 扣费、成本、对账和零调用证明。
- 用户确认、发布放行和审计日志。

模型可以建议，但不能覆盖这些边界。

### LG7 五个案例只用于验收，不用于教答案

水果、黄金礼品、TikTok 直播公会、系统自营销、宝妈素人是冻结回归案例：

- 不进入生产 Prompt。
- 不作为行业 Skill 标准答案。
- 不作为检索增强的隐藏金答案。
- 不用关键词 denylist/allowlist 修过测试。
- 不因看到结果而改评分阈值。

每轮候选还必须通过冻结后才揭晓的跨行业 unseen。seen 通过只能说明没有回归，不能说明泛化。

### LG8 营销质量有独立证据等级

所有能力声明使用五级状态：

1. 代码存在。
2. 机械合同通过。
3. 真实模型或供应商调用可达。
4. 真实业务盲评通过。
5. 真实发布与复盘通过。

低级状态不能冒充高级状态。一次成功、测试全绿、合法 JSON、低 Token 或页面可点击均不能单独成为业务验收。

### LG9 新复杂度必须先举证

新增永久默认的 Agent 编排、硬闸门、状态表、运行时或长期上下文前，必须提交一份最小变更证据：

- 哪个冻结 unseen 真实失败。
- 当前基线输出、成本、时延和事实错误。
- 为什么现有 Lead 或现有工具无法解决。
- 最小候选改动是什么。
- 与未改基线的盲测结果。
- 是否改善质量，同时没有不可接受地增加幻觉、Token、时延和维护面。
- 失败时如何删除或回滚。

没有这份证据，不得以“以后可能有用”为由进入永久默认。可删除的 Skill、Prompt 或工具候选可先在隔离评测中试验；它们只有通过预先冻结的对照后才能进入默认上下文。候选失败后必须退役，不留在默认上下文。

### LG10 旧代码只做选择性移植

复用顺序固定为：

1. 先复用业务结论和失败测试。
2. 再复用类型合同、不可变账本和纯领域算法。
3. 核对许可证、来源、冻结提交和依赖。
4. 在当前模块化单体边界内重新实现或最小摘取。
5. 用当前测试证明没有引入第二状态机、第二真相源或付费旁路。

禁止整包复制旧仓、旧 Prompt、未提交工作树、缓存、密钥和历史运行产物。

## 7. 当时 v1.2 规格的审计结果与当前替代

当时 v1.2（v1.1 业务规格加本次审计护栏）已经避开了一部分旧坑：

- 模块化单体，不先拆大量微服务。
- 当时使用 PostgreSQL 单一事实来源；当前 v1.4 已用“客户 Project/Artifact 本地加密真相＋云端身份/账本/供应商操作商业真相”的显式分治取代这一总体表述，禁止再建云端客户内容库。
- 五个真实项目包含直播公会和系统自营销。
- 用户手动发布，首版不自动登录平台发布。
- TopicCard 级主体风险记录；只在重大定位变更或不可逆执行时要求精确 Artifact/ID 确认。
- 零调用不创建 ProviderCostInput 或成本行。
- 真实供应商调用必须处理崩溃窗口和对账。
- 真人、数字人和 AI 情景剧是表现路由，不默认真人出镜。

仍需以本文件补强：

1. 多个 Agent 角色是逻辑职责，不是固定调用阵列；单一 Lead 仍是最终业务权威。
2. 五问是就绪状态，不是固定逐题硬门。
3. 五个案例是评测锚，不是生产提示词答案。
4. 增加 USER_FACT、EXTERNAL_EVIDENCE、MODEL_INTERPRETATION、CREATIVE_HYPOTHESIS、UNKNOWN、ACTUAL_RESULT 六类状态。
5. 内容世界与表现形式分离，商业承接不能决定内容根。
6. 新增永久默认 Agent 编排、硬门和长期状态必须先通过复杂度证据门；可删除 Skill/Prompt/工具先进隔离评测。
7. 上线报告必须分别写“工程、机制、真实调用、业务盲评、真实发布”状态。
8. 继续永久禁止当前系统依赖或调用 map-marketing-content-world 技能；相关旧内容只能作为历史证据，不能成为运行时。

## 8. 实施前强制复核问题

任何实施任务开始前，执行者必须回答：

1. 这项改动修的是哪一个真实业务失败？
2. 它改变的是模型软判断，还是代码硬边界？
3. 是否增加第二权威、第二真相源或第二状态机？
4. 是否把五个案例答案写进了系统？
5. 是否默认了用户未提供的经历、能力、人物、资源、地区或出镜方式？
6. 是否可能产生付费调用；代码如何限制、去重和对账？
7. 代码测试通过后，还需要什么真实业务证据？
8. 如果候选失败，哪些文件、Prompt、Skill、表和路由会被彻底退役？

任一问题答不清，不进入实现。

## 10. 最终决策

当前项目不是“第六版再修一次”，而是继承六轮证据后的新基线：

- 业务上，以五问、交易角色、受众、内容世界、证据化选题和表现路由为主线。
- Agent 上，以一个总编权威和按需专家为主线。
- 工程上，以领域分治的权威事实为主线：客户内容/项目真相在本地，身份/账本/供应商操作的商业真相在云端；两者都保留不可变谱系、显式的不可逆授权、代码预算和供应商对账。
- 评测上，以冻结案例、跨行业 unseen、盲评和真实发布为主线。
- 迁移上，只迁经过审查的结论、合同、测试和纯算法，不迁整套旧系统。

以后若新方案与本文件冲突，必须先写明：它试图推翻哪条历史结论、新证据是什么、影响哪些规格与计划、如何回滚。没有新证据，沿用本文件。
