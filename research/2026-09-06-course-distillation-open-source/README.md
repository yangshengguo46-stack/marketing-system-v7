### course2md 的几个关键细节

1. [pipeline.rs](https://github.com/mizorewww/course2md/blob/5a74063216a8e4dc9e4b2399d10a138883d2f1c4/src/pipeline.rs) 在段落合并和可选模型校对前保存 `timeline.jsonl`。这让我们能回到原始 ASR，而不必把校对后的文字当作原课。
2. [scene.rs](https://github.com/mizorewww/course2md/blob/5a74063216a8e4dc9e4b2399d10a138883d2f1c4/src/scene.rs) 比较采样帧并等待稳定状态，可设感兴趣区域。它适合稳定课件；根据这一机制推断，短暂的批注、手势及修改中间态可能需要额外采样，尚未在本课视频上验证。
3. [timeline.rs](https://github.com/mizorewww/course2md/blob/5a74063216a8e4dc9e4b2399d10a138883d2f1c4/src/timeline.rs) 主要按语音时间中点归属画面，并尝试在自然句读处分开跨页文字。这是时间关联，不证明画面与讲解在语义上相互支持；跨多个画面的完整案例还需重新组织。
4. [llm.rs](https://github.com/mizorewww/course2md/blob/5a74063216a8e4dc9e4b2399d10a138883d2f1c4/src/llm.rs) 的可选模型步骤主要校对文字，可附截图，不承担教学方法提炼。我们可将原始材料交给既有 Lead 处理，无需接入它的另一套模型调用配置。
5. [fetch.rs](https://github.com/mizorewww/course2md/blob/5a74063216a8e4dc9e4b2399d10a138883d2f1c4/src/fetch.rs) 使用 yt-dlp，单次不抓播放列表，并显式处理 B站 412。换工具不能保证解决源站访问；本地原视频是后续可选输入。

仓颉的 [输出检查脚本](https://github.com/kangarooking/cangjie-skill/blob/34e34bc5c7eb1c7d6cae9f84a9bcc62acb2a971b/scripts/run_output_evals.py) 准备匿名对照材料并做包含文本、正则、文件和 JSON 路径等机械检查。人物型仓颉的质量脚本也包含大量结构检查。它们的成功状态不等于真实故事改善。

## 从样例得到的最小处理流程

1. **登记材料。** 一课一条清单，记录来源、版本、时长、文件校验值、字幕/画面状态。目录存在、文件取得、转录完成、实际读完分别记录，失败课不会被悄悄跳过。
2. **保留原始时间线。** ASR 和画面引用保留原始时间；校对以修订形式另存。出现同音词、零时长或可疑重复时标记待核，不直接删改原始记录。
3. **组织完整教学片段。** 以一个问题、示范或案例的开始和结束为单位；一个案例跨页时仍保留整体。用起止时间及原始记录 ID 回查，少量相邻上下文帮助处理半句和跨段指代。
4. **提取关系。** 在片段中区分问题、判断、方法、示范、结果、例外；某项未讲到就记缺失。电影分析、课堂改稿和作者创作实录分别标明，不互相升级。
5. **回查后提炼。** 把有证据的方法与我们提出的迁移用法分开。跨课核对同一概念的补充、限制和矛盾，再组织能力关系；先完整保留素材，随后压缩使用入口。
6. **用新故事检查用途。** 同题比较直接创作、阅读课程材料、使用提炼方法三种结果，保留实际稿件与具体问题。当前尚未执行这一步。

## 是否开发工具

建议先复用课程采集和时间线保存，工具选型仍待真实视频试验。当前证据还不足以判断 course2md 在本课的板书、对白示范、插播电影上表现是否足够好。

如果视频试验暴露缺口，需要补的是一个供原生 Lead 调用的小型材料工具，输入本地视频和字幕或已有时间线，输出可回查的材料包。最先考虑的功能仅包括：

- 按时间范围读取讲解及前后文，返回明确的已读范围和缺失状态；
- 对“看这里、我改一下”等确指画面的片段补取前、中、后画面，保留发生过的修改；
- 检查教学片段的引用是否真实存在、哪些时间段未处理，以及重新提炼时哪些判断需要复核。

这些能力不要求桌面外壳、后台服务、新运行时、数据库或评审平台。语义判断仍由现有 Lead 完成。拿到原视频后先比较现成工具的实际结果，确认缺口再实现；本轮没有开始编写工具。
