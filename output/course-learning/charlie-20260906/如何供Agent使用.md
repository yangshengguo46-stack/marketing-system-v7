# 怎样把课程变成 Agent 能用的方法

**2026-09-09最新顺序：先完成全套贯通课件，再做业务实作和横向比较。** 现有逐课全文保留，本轮已交付[四卷课件与总导读](全课课件/README.md)，接起全课工作过程、案例推演、作业承接与后课修正；不从下面的候选方法直接启动局部试验。见[本轮整理约定](全课课件/整理约定.md)。

采用完整课程资料与小范围操作方法配合的方式。课程资料让 Agent 找到上下文、示范和真实作业；方法说明让 Agent 知道在当前任务中怎样使用这些材料。Obsidian 方便人检查和补充同一批文件，现有原生 App Server 继续负责执行。

2026-09-08用户反馈显示，仅有局部写作方法仍不足以形成清楚的整体表达。新增[课程核心方法论](课程核心方法论.md)，串联人物为什么行动、事情如何检验其关系/判断、结尾产生什么意味。整体不清时先处理这些联系，局部已经明确时再选具体方法。新步骤尚未用新一轮原生写作验证。

## 先还原学习过程

从[全套目录](全套目录.md)按老师原编号读。每课保留讲解顺序、案例、作业与实际引用的前课。第一次学习时，应顺着这条线，避免只看到“八要素”或“二次动作”就越过素材准备，直接交一个看似完整的故事。

课程路线用于本项目的内部学习与方法验证。实际创作以用户已经提供的材料、现有稿件和目标为起点，由Lead识别所处阶段，再读取必要方法；用户的正常业务流程仍是创作任务。

已核到的例子是：第一课写下真实幻想，第二课将它作为素材继续处理。对 Agent 而言，“真实”需要有用户材料或可追溯的观察支持；它不能伪称拥有个人经历。开发练习可以采用明确标注的虚构设定，但这与老师面向真人布置的自我观察作业不同，迁移时要记下这个差别。

## 再提炼能执行的办法

提炼单位是一个具体问题的处理过程，而非“一课一个 Skill”。每个候选方法应能回答下面这些问题，并引用实际课程段落：

| 内容 | 要说清什么 |
| --- | --- |
| 何时使用 | 当前材料或草稿出现什么问题；不适用的情形是什么。 |
| 需要什么输入 | 要有生活材料、人物处境、已有事件还是完整草稿；哪些事实还缺失。 |
| 判断和动作 | 老师观察了什么、怎样选择、怎样改动，按什么顺序推进。 |
| 课堂示范 | 至少连回一个有上下文的例子；区分老师现场示范与他对成片的解释。 |
| 本次交付 | 应产出素材、故事概述、完整正文还是局部改稿，不能用分析表代替要求的作品。 |
| 如何检查与返工 | 对照本次作业的具体要求，指出正文中的问题，再重写受影响的部分。 |
| 已知边界 | 原课没有讲、转录不清、画面尚未核查、迁移后尚未试过的内容。 |

这张表是我们的整理办法，不能冒称老师布置了这套表格。课程没有给固定步骤的地方，保留概念和案例，不强行改造为算法。

## 用实际作业检查能不能用

按[原课作业](原课作业.md)中找到的要求保存输入、提交稿和修改稿。老师若展示讲评，连回具体片段；老师没有给出的标准，不补写成他的标准。系统练习与用户实际业务分开记录，虚构材料不作为客户洞察。

一次练习至少要能看出：是不是完成了题目；读者能否理解发生了什么；所学办法在哪个具体地方改变了稿子；是否引入新的不可信之处。模型编辑意见可辅助指出问题，不能代替用户或读者的判断。旧稿失败仍保留，不靠多跑几次后只展示最好的一稿来证明方法稳定。

本轮先完成全课整理，再按第4—5课规格执行一份完整作业；前轮片段式故事试验仍停止。课程资料齐全、文件读取成功和真实模型请求成功，各自只能证明对应的工作，不能证明故事好看。

## 现在怎样调用

在当前项目给 Lead 一个实际写作/改稿任务，并指定：

> 先读 output/course-learning/charlie-20260906/Agent入口.md，按当前问题选方法和课堂示范。完成本次要求的作品，用原生作业链保留输入、稿件和实际返工。

然后提供人物材料或现有稿及希望改动的具体地方。入口并不要求每次通读全部课程；学习原课作业时，才顺着完整学习路线核对题目和承接。当前是显式给定资料的调用，尚未成为系统默认自动触发的 Skill。

## 最后怎样放进 Skill

课程讲义、例子、时间点和作业继续保留为普通资料。某个办法在实际练习中显示出可重复使用的价值后，Skill 只保存用途、输入要求、操作步骤、相关材料位置和返工提示。Lead 根据当前任务读取相关课程和例子，不把约63小时课程一次性塞进上下文。

暂不安装一个包办写作、起号和营销的总 Skill。编剧课中的叙事方法也不能自动代表产品研究、账号定位或音乐声音方面的能力；这些部分仍应依据真实任务和对应材料发展。
