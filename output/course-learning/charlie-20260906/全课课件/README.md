## 先看这套课究竟在教什么

这套课的中心，可以整理为：**从对人的观察出发，让一个具体的人为自己在乎的东西行动；事情的发展检验他的办法、关系或信念，结果让观众对这个人及其处境产生理解和感受。** 这是依据全课所作的贯通概括，不是老师原话，也不是每篇故事的固定公式。

起承转合解决事情怎样组织，还不能单独回答为什么值得讲。人物、事件、表达是同一作品的三个侧面：先理解这个人为什么想要，再看他为此怎么做；别人、环境和他自己的局限怎样回应；他坚持、改变或付出什么；观众据此看见了什么。表达不是在结尾替故事写一句道理，也不强制所有人物都成长。P092中较坚定的安迪，是这条概括需要容纳的例外。

第3课想殉职的警察最直观：反常身份先让人问为什么，保护女儿的欲望解释了求死这个办法；后来想活与不愿活的局面互换，人物才可能通过新的行动重新理解保护。到第8课老师换了抚恤金版本，具体事件又不断被改动：加薪会过早解除缺钱，必须取消；光有表彰不等于担当，开场失职需要产生后果；女儿的认可放在行动之后才有依据。学到的不是“警察故事要这样写”，而是每一个修改怎样影响整篇。

第34课又把镜头拉回一场。知道“孩子可怜”只是表达诉求，写她懂事、努力不添麻烦，再让一个压不住的小愿望显露，才让人从具体行动读到需要。P001随后提醒：即使结构任务全对，若一段只有手机信息和对白解释，也还没有把事情写出来。第1课的生活细节、前中段的结构与关系、后段的观众感受，到这里重新在同一场戏里汇合。

因此整课的递进不是背更多名词，而是承担越来越完整的创作责任：从材料形成故事；把故事展开成可呈现的事件；让人物和关系经得起过程检验；组织观众的知道、担心与期待；写出具体场面，再根据实际稿子整体修改。类型、十序列、十五节拍、小三角分别帮助其中一部分，不能互相替代，也不能给所有篇幅、风格套同一比例。

## Agent怎样使用，才能少学半截

先读本导读和作业接续，理解整课各部分的责任。进入某项工作时，读完整的相关课节和其前后修正，再从讲义链接读案例的起点、过程与结论。长文件分段读取并检查工具是否截断；整册用于连续阅读和定位，不需要一次全部塞进模型请求。

使用时要分清四类材料：用户实际提供的事实、课堂已有案例、老师现场试设的变体、Agent后续自行创作的内容。课堂没有展出的学生原稿不能补造；教学中的一次备选结尾不能悄悄与另一版本合并。引用方法的工作笔记只需说明它解决稿中的什么具体问题、依据哪个完整示范、为何在此适用，不要求用户先替产品学完整套课。

例如稿子全在介绍背景，要接读第7、14课与P001；稿子有事件却没有中心，要回人物欲望、关键选择与结果，再读第15、21、24课；稿子讲清楚但不吸引，要检查第16、25、27、30课的观众位置；单场顺直则接第14、34课。以上是读取入口，不是已验证的自动写作程序。将来发现方法无效，应从实际作品找问题，不能用“没学完更多课”无限推迟检验。

目前采用普通Markdown课件与来源资料，既可供Agent读取，也可在Obsidian中阅读；不需要引入另一运行时或重建知识平台。是否把其中稳定有效的操作封装成Skill，留待整课后的实际检验。编剧能力也只承担一站式产品的一部分，商业研究、IP方向、画面、声音、音乐、表演、剪辑与传播仍需各自的材料和实践。
